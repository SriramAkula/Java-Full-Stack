🔵 1. STRING — IMMUTABLE, SPECIAL, INTERNALLY OPTIMIZED
✔ String is Immutable

Once created, contents cannot change.

Any modification results in a new String object.

Immutability enables:

Security

String Pool

Hashcode caching

Thread safety

✔ String Pool (SCP)

"Hello" goes to the SCP.

"Hello" == "Hello" → true (same reference).

new String("Hello") → heap object, not pooled.

intern() returns SCP reference.

✔ Internal Representation

Java 8 and below: char[] value

Java 9+: byte[] value + byte coder
(Compact Strings: LATIN-1 or UTF-16)

✔ HashCode Caching

First hashCode() call computes and stores the hash.

Subsequent calls are O(1).

✔ Concatenation Behavior

"A"+"B" → compile-time optimization → pooled.

a + b (variables) → uses StringBuilder internally → heap object.

✔ substring() Behavior

Java 7: shared char[] → memory leak

Java 8+: creates new char[] → fixed

🔵 2. STRINGBUFFER — THREAD SAFE AND MUTABLE
✔ Mutable

Operations modify same internal buffer.

✔ Thread-safe

Every method is synchronized.

Safe for multi-threaded environments.

Slower than StringBuilder due to locking.

✔ Internal Storage

Uses char[] value (still in Java 17/21).

Capacity grows by formula:

newCapacity = oldCapacity * 2 + 2

✔ Core Methods (NOT in String)

append()

insert()

delete(), deleteCharAt()

replace(int, int, String)

reverse()

capacity()

ensureCapacity()

setLength()

trimToSize()

🔵 3. STRINGBUILDER — FASTEST MUTABLE STRING
✔ Mutable & Not Thread-safe

No synchronization → fastest for single-threaded use.

✔ Same methods as StringBuffer

append(), insert(), delete(), reverse(), etc.

Same capacity growth behavior.

✔ Best for:

Heavy string manipulation

Loops

Complex concatenation

Building dynamic SQL, logs, XML, JSON, etc.

🔵 4. KEY DIFFERENCES (MOST ASKED IN INTERVIEWS)
Topic	String	StringBuilder	StringBuffer
Mutability	Immutable	Mutable	Mutable
Thread Safety	Safe (immutable)	❌ Not safe	✔ Safe (synchronized)
Performance	Slow	Fastest	Slower (lock overhead)
Storage (Java 9+)	byte[]	char[]	char[]
Best Use	Constants	Loops, large manipulation	Multithreaded code
🔵 5. METHODS EXCLUSIVE TO BUFFER/BUILDER (NOT IN STRING)
These do NOT exist in String:

append()

insert()

delete()

deleteCharAt()

reverse()

ensureCapacity()

setLength()

trimToSize()

Because String cannot be modified.

🔵 6. CAPACITY BEHAVIOR
Default:

Empty StringBuilder → capacity = 16

With content → capacity = content.length + 16

Expansion Formula:
newCapacity = oldCapacity * 2 + 2

Methods:

capacity()

ensureCapacity()

trimToSize()

🔵 7. TRICKY BEHAVIOR RULES YOU LEARNED
✔ delete(start, end)

Deletes start to end-1

end is exclusive

✔ insert(index, str)

Shifts all characters to the right

✔ setLength()

If length ↓ → truncates

If length ↑ → adds \u0000 null chars

✔ reverse()

In-place, no new buffer

✔ append()

Uses existing char[] unless full

Expands with doubling rule

🔥 8. INTERVIEW TAKEAWAYS

String → safe, immutable, SCP, cached hash, fast for reads.

StringBuilder → fastest for modifications.

StringBuffer → safest for multithreaded modifications.

"A"+"B" is optimized, but a+b is not.

substring() changed behavior after Java 7.

StringBuilder/Buffer NEVER use byte[] (only String uses compact strings).
